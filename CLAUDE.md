# CLAUDE.md — Arabic Kids

Context note for Claude sessions. Keep this updated when structure / conventions change.

## Product

Android app teaching Arabic to children (ages 3–10). Multi-language UI (10 langs). Package `com.hsrconsulting.arabickids`. Play Store: designed-for-families, COPPA-compliant.

## Tech stack

- **Android host** (Kotlin) — thin WebView shell, AdMob, Firebase (Analytics/Auth/Firestore/Crashlytics), Play Billing, TTS, SpeechRecognizer, SoundPool.
- **UI & gameplay** — HTML/JS/CSS inside `app/src/main/assets/web/`. No framework — vanilla JS SPA with a `render()` loop over a `renderers` map keyed by `AppState.screen`.
- **Shared KMP module** — `shared/` (stubs only; gameplay logic still lives in JS).
- **Build** — Gradle Kotlin DSL. AGP 8.7. Firebase BoM 32.7. Google Services + Crashlytics plugins applied.

## App state model (JS)

`AppState` (in app.js) persists to `localStorage[ak_{name}]` + Firestore (`profiles/{hash(name+code)}`). Key fields: `user, lang, theme, score, level, lessons, quizzes, learnedLetters[], earnedBadges[], visitedCategories[], difficulty, premium, streak:{current,longest,lastActive}, dailyDone, _pathOrigin, _dailyOrigin, _firstTime, _onbSlide`.

`save()` auto-pushes to cloud if `Android.cloudSave` is available (no-op otherwise). `load(name)` reads local; `doLogin` falls back to `Android.cloudLoad` + `_onCloudLoad` callback.

## Core conventions

- **Harakat** — every word exposed in `ALPHABET.w/ex` + `WORD_CATEGORIES.*.words[].ar` is vocalized via an IIFE at bottom of data.js that rewrites these fields using `_HARAKAT_DICT`. So the app displays *and* speaks vocalized forms. Non-dict words pass through unchanged.
- **TTS digit strip** — `speakArabic` strips `0-9`, `٠-٩`, `۰-۹` + trailing whitespace before speaking. Prevents "wāḥid wāḥid" for numbers formatted as `وَاحِد ١`.
- **Back navigation** — `sectionBack()` (JS) + `handleAndroidBack()` (JS called from Kotlin) check `_pathOrigin` → return to path, `_dailyOrigin` → return to home, else use a `parents` map (letterDetail→alphabet, wordList→words, letterTraceLesson→letterTraceMenu), else `goHome()`.
- **Scroll reset** — `navigate()` calls `window.scrollTo(0,0)` at end; letter prev/next handlers do the same inline.
- **Home idempotency** — `goHome()` early-returns if already on dashboard (avoids dead renders on the 🏠 button).
- **Signed builds** — `keystore.properties` at repo root (never committed) configures the release signing config. Release plays a different applicationId suffix (`.debug` in debug variant). Play Store uploads must always use `versionCode` greater than any previously published.

## Testing

- **Target device**: Samsung S25 Ultra (SM-S938B, transport_id varies) and Xiaomi Pad 5 (nabu).
- **Commands**:
  ```bash
  ./gradlew :app:assembleRelease       # → app/build/outputs/apk/release/app-release.apk
  ./gradlew :app:bundleRelease         # → app/build/outputs/bundle/release/app-release.aab (Play upload)
  adb install -r app/build/outputs/apk/release/app-release.apk
  ```
- **Logs**: `adb logcat -d --pid=$(adb shell pidof com.hsrconsulting.arabickids) | grep ArabicKids`
- **Launch**: activity isn't exported — use `adb shell monkey -p com.hsrconsulting.arabickids -c android.intent.category.LAUNCHER 1`.

## Firebase setup (project: `arabic-kids`)

- **Authentication** — Anonymous provider enabled. Sign-in happens on every MainActivity onCreate via `Firebase.auth.signInAnonymously()`.
- **Firestore** — Collection `profiles/{md5key}` with `{state: string, updatedAt: long}`. Rules: `allow read, write: if request.auth != null;`.
- **Crashlytics** — Auto-init via ContentProvider. No userId attached (COPPA).
- **Analytics** — child-directed treatment + ADID/SSAID collection disabled.
- `app/google-services.json` contains both `com.arabickids.app` + `com.hsrconsulting.arabickids` clients. Missing `firebase_url` → Realtime Database not configured, we use Firestore instead.

## Difficulty modes

- `toddler` 🧸 (3–5) — 5 letters, 2 options, simplified dashboard (6 tiles), big touch targets via `body.mode-toddler` CSS.
- `beginner` 🌱 — 10 letters, 3 options, 3 starter categories.
- `normal` ⭐ — 28 letters, 4 options, all content.
- `advanced` 🔥 — 28 letters, 4 options, reversed quizzes, unlocks reading texts.

## Working style reminders

- User speaks French. Replies concise, bullet-first.
- Prefer `Edit` over full rewrites. Never `Bash cat/grep/find` when a dedicated tool works.
- Build + install after material changes; the user often asks "install" to mean rebuild+push.
- Verify in logcat when the user reports "ça marche pas".
- Every user-facing string needs all 10 langs (fr, en, es, de, tr, hi, id, it, nl, pt).
- When touching `data.js`: the IIFE at the bottom applies harakat — don't duplicate entries elsewhere.
