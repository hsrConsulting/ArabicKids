# CLAUDE.md — Arabic Kids

Context note for Claude sessions. Keep this updated when structure / conventions change.

## Product

Android app teaching Arabic to children (ages 3–10). Multi-language UI (10 langs). Package `com.hsrconsulting.arabickids`. Play Store: designed-for-families, COPPA-compliant.

## Tech stack

- **Android host** (Kotlin) — thin WebView shell, AdMob, Firebase (Analytics/Auth/Firestore/Crashlytics), Play Billing, TTS, SpeechRecognizer, SoundPool.
- **UI & gameplay** — HTML/JS/CSS inside `app/src/main/assets/web/`. No framework — vanilla JS SPA with a `render()` loop over a `renderers` map keyed by `AppState.screen`.
- **Shared KMP module** — `shared/` (stubs only; gameplay logic still lives in JS).
- **Build** — Gradle Kotlin DSL. AGP 8.7. Firebase BoM 32.7. Google Services + Crashlytics plugins applied.

## App state model (JS)

`AppState` (in app.js) persists to `localStorage[ak_{name}]` + Firestore (`profiles/{hash(name+code)}`). Key fields: `user, lang, theme, score, level, lessons, quizzes, learnedLetters[], earnedBadges[], visitedCategories[], difficulty, premium, streak:{current,longest,lastActive}, dailyDone, _pathOrigin, _dailyOrigin, _firstTime, _onbSlide`.

`save()` auto-pushes to cloud if `Android.cloudSave` is available (no-op otherwise). `load(name)` reads local; `doLogin` falls back to `Android.cloudLoad` + `_onCloudLoad` callback.

## Core conventions

- **Harakat** — every word exposed in `ALPHABET.w/ex` + `WORD_CATEGORIES.*.words[].ar` is vocalized via an IIFE at bottom of data.js that rewrites these fields using `_HARAKAT_DICT`. So the app displays *and* speaks vocalized forms. Non-dict words pass through unchanged.
- **TTS digit strip** — `speakArabic` strips `0-9`, `٠-٩`, `۰-۹` + trailing whitespace before speaking. Prevents "wāḥid wāḥid" for numbers formatted as `وَاحِد ١`.
- **Back navigation** — `sectionBack()` (JS) + `handleAndroidBack()` (JS called from Kotlin) check `_pathOrigin` → return to path, `_dailyOrigin` → return to home, else use a `parents` map (letterDetail→alphabet, wordList→words, letterTraceLesson→letterTraceMenu), else `goHome()`.
- **Scroll reset** — `navigate()` calls `window.scrollTo(0,0)` at end; letter prev/next handlers do the same inline.
- **Home idempotency** — `goHome()` early-returns if already on dashboard (avoids dead renders on the 🏠 button).
- **Signed builds** — `keystore.properties` at repo root (never committed) configures the release signing config. Release plays a different applicationId suffix (`.debug` in debug variant). Play Store uploads must always use `versionCode` greater than any previously published.

## Ads

- **Banner**: `AdView` in `activity_main.xml` (id `adView`), unit `admob_banner_id` in `strings.xml`. Loaded after UMP consent + `MobileAds.initialize` via `loadBannerAd()`. Lifecycle hooks (`pause`/`resume`/`destroy`) wired in `MainActivity`.
- **Interstitial**: real unit `admob_interstitial_id`. Tuned for kids — 90s warm-up after launch + 120s cool-down between two ads (in `_tryShowPendingAd`, `app.js`). Frequency thresholds: every 3 quizzes, every 6 letter views, every 5 memory wins, every 6 tracings, every 4 word readings, every 3 text readings. Triggers queue `_adPending` flag, shown on next navigation away.

## Audio failure detection

`AudioSystem` (audio.js) tracks consecutive silent `speakArabic` calls — silent = MP3 not in `_AUDIO_DICT` AND `Android.speakArabic` returned false. After 3 silent calls in a session, `_showTtsMissingHint()` popup fires once with a deeplink into system TTS settings (`Android.openTtsSettings`). `Audio.onplay` resets the counter so any working playback path keeps the popup dormant. Also auto-fires once at app launch via `onTtsStatus(false)` callback when the TTS engine reports no Arabic voice.

## Interactive stories

- Schéma alternatif aux stories linéaires (lines+questions). Marqueur `interactive: true` dans la story → `renderStory` délègue à `renderInteractiveStory`.
- Format : `nodes{}` (object keyé par id), entry point = `'start'`. Chaque node a `ar`, `tr{multilang}`, et soit `choice {q{multilang}, options[{emoji, label{multilang}, next}]}` soit `ending: true`.
- État runtime : `AppState._storyNode` (default `'start'`), reset à chaque `openStory()`.
- Audio Polly auto-joué à 400ms après render de chaque nœud.
- Story-card affiche chip 🔀 "Interactive" si `s.interactive`.
- Première story livrée : `market` (Ahmad au marché → fruits/légumes → 4 fins possibles).

## Pedagogy: corrective feedback + spaced review

- **Corrective feedback** — all MCQ quizzes go through `quizAnswer` + `_optCls(qd,o,i)`. On a mistake the right option gets `.reveal` (dashed green pulse), the prompt audio is replayed (`q.speak||q.arabic||q.letter`), and the pause is 2.6s instead of 1.2s.
- **Review deck (Leitner)** — `AppState.review = {"L:ب"|"W:<ar>": {b, due}}`. Wrong answer → box 0, due today. Correct answer *once due* → box+1, next due +1/+3/+7 days; past last box → removed. Key derived by `_reviewKey` from `_REVIEW_LETTER_TYPES` / `_REVIEW_WORD_TYPES` (or `q.reviewKey`). Surfaces: orange dashboard card (`renderReviewCard`, only when due), 🔁 tile at top of quiz hub, 🔁 section in parent child detail.
- **Letter check "I know it!"** (`startLetterCheck`) — round 0: hear the letter, tap it (isolated). Then 1/2/3 rounds (beginner/normal/advanced) "find the initial/medial/final form" among same-position forms (1 twin-family distractor + random). Non-connectors (ا د ذ ر ز و) only get the final-form round. `lc.options` = `[{label, correct}]`, answered by index.
- **Sound quizzes** — one engine `SOUND_QUIZZES` + `_startSoundQuiz(type)` + `renderSoundQuiz`: 🗣️ `syllables` (short vowels, alternating vowel / consonant discrimination), 🐍 `long` (بَ vs بَا, بَا/بُو/بِي), ✨ `tanwin`. Long-vowel keys `L+V+madd` have IPA MP3s (generator `syllable_tasks`, not for alif).
- **Twin letters quiz** 👯 (`startQuizTwins`) — `TWIN_FAMILIES` (ب ت ث ن, ج ح خ, …): hear one, pick among look-alikes.
- **Guided reading** 🧱 (`startBlend`, screen `blend`) — `BLEND_WORDS` in data.js (`ar` + explicit `syl[]`, easiest first; every `ar` must exist in WORD_CATEGORIES). Tap syllables right→left, word merges + plays, then pick the emoji. Syllable MP3s: `blend_syllable_tasks()` + `syllable_ipa()` in the generator.
- **Sun & moon letters** 🌞 (`startQuizSunMoon`) — `SUN_MOON_WORDS` (`ar` with ال, `base` = category word, `sun` bool). After answer the ل is greyed (`.lam-silent`) or green.
- **Adaptive pools** — `_practiceLetters(min)` = learned letters + letters in the review deck (fallback: difficulty slice). Used by letters, harakat, positions and sound quizzes.
- **Daily challenge** — if review items are due at the first look of the day, the challenge is 🔁 review (`dailyReviewDay`/`dailyIsReview` persisted, frozen for the day).
- **Learning path skills** — step `type:'skill'` (`SKILLS` map in app.js); done when the quiz ends ≥50% (`AppState.skillsDone`). An undone skill step with a later step done is a **catch-up** (`isPathCatchUp`): shown ⭐, playable, never blocks → advanced kids aren't pushed back. Progress % = done steps / total.
- Adding Arabic content ⇒ run `python3 tools/generate_audio.py` (skips existing MP3s). New `ar:` strings + blend syllables are picked up automatically.
- `_resetProgress()` runs before `load()` / register / cloud load so a profile never inherits the previous child's streak/letterStats/review.

## Streak freeze

- `AppState.streak.freezes` (entier, max `MAX_FREEZES=2`).
- **Gain** : +1 freeze tous les 7 jours de streak (cap à 2).
- **Consommation** : si `lastActive == day-before-yesterday` (1 jour raté pile) ET `freezes > 0` → -1 freeze, streak continue. 2 jours+ ratés = reset normal.
- **Notification** : `AppState._streakSavedPending` levé → popup ❄️ "Streak sauvé !" au prochain `render()` via `_maybeShowStreakSavedPopup()`. One-shot.
- **Affichage** : badge dashboard `🔥 5 days · ❄️ 1` (si freezes > 0). Parent dashboard inclut aussi le compteur.

## Parent code

- Code 4 chiffres **distinct** des codes enfants, stocké dans `localStorage[ak_parentCode]` (device-wide, pas par profil).
- Au 1er déclenchement de `_parentGate` (changer difficulté, logout, retirer profil, ouvrir parent dashboard) → popup **CREATE** avec input nouveau + confirme.
- Aux suivants → popup **VERIFY** classique.
- **Pas de mécanisme de reset** : si le parent oublie le code, il doit désinstaller l'app (perd localStorage local — les profils restent en Firestore si saved après le tag `seenBy`, donc récupérables via cloud recovery au prochain install). À documenter dans le store si besoin.

## Cloud sync model

- Chaque `cloudSave(name, code, json)` ajoute le `uid` anonyme au champ `seenBy[]` du doc Firestore via `arrayUnion`.
- Au boot, `cloudListSeenProfiles()` query `where seenBy contains uid` → propose une recovery dialog (`_showCloudRecoverDialog`) pour les profils absents de localStorage. Idéal après réinstall / nouveau device.
- Les profils créés AVANT cette feature n'ont pas le tag `seenBy` et ne seront pas auto-retrouvés. Ils peuvent toujours être récupérés via login manuel (nom + code).
